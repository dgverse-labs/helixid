# STORY 5 — JWT Session Bridge

## Overview

Bolt JWT session issuance into the existing VP verify flow. When an external service passes `"session": true` in `POST /v1/vp/verify`, Helix ID runs the full existing verification pipeline and — on success — also returns a signed JWT. The external service caches Helix ID's JWT public key (fetched once from `GET /v1/sessions/public-key`) and verifies all subsequent calls locally without touching Helix ID. JWT TTL is 10 minutes, configurable via `JWT_SESSION_TTL_SECONDS`.

This story touches the VP verify route and service, helix-core (JWT schema, new error codes), and the SDK (session-aware verify method).

---

## 5.1 — Environment Variables

Add to `.env.example` and `helix-core/src/config/`:

```
HELIX_JWT_SIGNING_KEY=        # Ed25519 private key hex — separate from HELIX_SIGNING_KEY
HELIX_JWT_PUBLIC_KEY=         # Corresponding public key hex — served at /v1/sessions/public-key
JWT_SESSION_TTL_SECONDS=600   # Default 10 minutes
```

**SA rule:** `HELIX_JWT_SIGNING_KEY` is a new secret. It must be generated by `scripts/setup.ts` alongside the existing VC signing key. It must never appear in any log or audit entry. Add to the AL-2 forbidden fields list in the constitution.

Config module (`helix-core/src/config/index.ts`) adds:
- `jwtSigningKey: string` — required, validated present on startup
- `jwtPublicKey: string` — required
- `jwtSessionTtlSeconds: number` — default 600

## 5.2 — helix-core Additions

### JWT Schema — `helix-core/src/schemas/jwt.ts`

```typescript
interface HelixJWTPayload {
  // Standard JWT claims
  iss: string;          // Helix ID's DID — did:hedera:testnet:<operator>
  sub: string;          // agentDid
  iat: number;          // issued at (unix seconds)
  exp: number;          // expiry (unix seconds) — iat + JWT_SESSION_TTL_SECONDS
  jti: string;          // unique JWT ID — cuid(), for future revocation

  // Helix ID custom claims
  userDid: string;
  targetService: string;
  scopes: string[];     // privilege scopes from the verified VC
  vpId: string;         // the vpId that was consumed to issue this JWT
}
```

Export Zod schema `HelixJWTPayloadSchema` and inferred type `HelixJWTPayload`.

### JWT Utilities — `helix-core/src/crypto/jwt.ts`

Uses `@noble/curves/ed25519` only — no `jsonwebtoken` or `jose` dependency. JWT is constructed manually: header + payload base64url-encoded, signature via Ed25519.

**Why no jwt library:** The approved crypto list in DP-3 is `@noble/curves` and `@noble/hashes`. A JWT library would add an unapproved dependency for something achievable with approved primitives. Add a `decisions.md` entry confirming this decision.

```typescript
function issueJWT(payload: HelixJWTPayload, privateKeyHex: string): string
```

Steps:
1. Header: `{ "alg": "EdDSA", "typ": "JWT", "crv": "Ed25519" }`
2. Base64url-encode header JSON and payload JSON
3. Signing input: `base64url(header) + '.' + base64url(payload)`
4. `signBytes(utf8Bytes(signingInput), privateKeyHex)` — hex signature
5. Convert hex signature bytes to base64url (no padding)
6. Return `header.payload.signature`

```typescript
function verifyJWT(token: string, publicKeyHex: string): HelixJWTPayload
```

Steps:
1. Split on `.` — must have exactly 3 parts, throw `InvalidJWTError` if not
2. Decode header, assert `alg === 'EdDSA'`
3. Reconstruct signing input: `parts[0] + '.' + parts[1]`
4. Decode signature from base64url to bytes, hex-encode
5. Decode payload JSON
6. `verifySignature(utf8Bytes(signingInput), signatureHex, publicKeyHex)` — throw `InvalidJWTError` if false
7. Check `payload.exp > Math.floor(Date.now() / 1000)` — throw `JWTExpiredError` if past
8. Return parsed payload

```typescript
function decodeJWTUnsafe(token: string): HelixJWTPayload
```
Decodes payload without verifying signature — for SDK-side inspection only. Never use on the verification path.

### Error Codes — `helix-core/src/errors/codes.ts`

```typescript
JWT_INVALID: 'JWT_INVALID',
JWT_EXPIRED: 'JWT_EXPIRED',
JWT_PUBLIC_KEY_NOT_FOUND: 'JWT_PUBLIC_KEY_NOT_FOUND',
```

| Class | Code | HTTP |
|---|---|---|
| `InvalidJWTError(reason)` | `JWT_INVALID` | 400 |
| `JWTExpiredError` | `JWT_EXPIRED` | 401 |

### Audit Events — `helix-core/src/audit/events.ts`

```
JWT_ISSUED   — fields: jti, agentDid, userDid, targetService, vpId, expiresAt
JWT_REJECTED — fields: reason (internal only), requestId
```

## 5.3 — Database Schema

No new tables. JWT state is stateless — the JWT is self-verifying via the signature. If future revocation of JWTs is needed (enterprise tier), a `jwt_revocations` table would be added then. For core, expiry via `exp` claim is sufficient.

The existing `vp_ids` table already records `consumedAt` — the vpId carried in the JWT payload provides an audit linkage without additional storage.

## 5.4 — API Changes

### Modify `POST /v1/vp/verify`

**Request body — add optional field:**

```json
{
  "signedVP": { ... },
  "session": false
}
```

`session` is boolean, optional, default `false`. Add to OpenAPI spec and Fastify JSON Schema.

**Response 200 — unchanged when `session: false`:**

```json
{
  "valid": true,
  "agentDid": "...",
  "userDid": "...",
  "targetService": "...",
  "verifiedAt": "..."
}
```

**Response 200 — when `session: true`:**

```json
{
  "valid": true,
  "agentDid": "...",
  "userDid": "...",
  "targetService": "...",
  "verifiedAt": "...",
  "session": {
    "token": "<jwt>",
    "expiresAt": "<ISO 8601>",
    "publicKeyEndpoint": "/v1/sessions/public-key"
  }
}
```

**`VPService.verifyVP` changes:**

Add optional `issueSession: boolean` parameter. After step 13 (emit `VP_VERIFIED` audit event), if `issueSession` is true:

1. Extract `scopes` from embedded VC's `credentialSubject.privilegeScopes`
2. Build `HelixJWTPayload`: `{ iss: config.helixOperatorDid, sub: agentDid, iat: now, exp: now + jwtSessionTtlSeconds, jti: cuid(), userDid, targetService, scopes, vpId }`
3. Call `issueJWT(payload, config.jwtSigningKey)`
4. Emit `JWT_ISSUED` audit event — include `jti`, `agentDid`, `vpId`. Never include the token string itself.
5. Return JWT alongside normal result

### New `GET /v1/sessions/public-key`

Public endpoint. No authentication. Called once by external services to fetch Helix ID's JWT verification key.

**Response 200:**

```json
{
  "publicKeyHex": "<HELIX_JWT_PUBLIC_KEY>",
  "publicKeyMultibase": "<multibase encoding>",
  "alg": "EdDSA",
  "crv": "Ed25519"
}
```

Set `Cache-Control: public, max-age=3600` — the key changes rarely; external services can cache it for an hour.

Register in `helix-api/src/routes/vp/index.ts` alongside existing VP routes.

## 5.5 — SDK Changes

### `helix-sdk-js/src/client/HelixClient.ts`

Add method:

```typescript
verifyVP(signedVP: SignedVP, options?: { session?: boolean }): Promise<VPVerificationResult>
```

If `options.session` is true, passes `"session": true` to the API and returns the full result including the JWT.

Add method:

```typescript
verifySessionToken(token: string, publicKeyHex: string): Promise<HelixJWTPayload>
```

Calls `verifyJWT(token, publicKeyHex)` from helix-core — pure local operation, no network call. External services use this on every subsequent request.

Add method:

```typescript
fetchSessionPublicKey(): Promise<string>
```

Calls `GET /v1/sessions/public-key`, returns `publicKeyHex`. External services call this once and cache the result.

Add to `helix-sdk-js/src/http/HttpAdapter.ts`: error mapping for `JWT_INVALID`, `JWT_EXPIRED`.

## 5.6 — Tests

### Unit Tests — `helix-core/tests/unit/crypto/jwt.test.ts`

- `issueJWT` produces a three-part dot-separated string
- `verifyJWT` with correct key returns payload matching input
- `verifyJWT` with wrong public key throws `InvalidJWTError`
- `verifyJWT` with tampered payload (change one char) throws `InvalidJWTError`
- `verifyJWT` with expired `exp` throws `JWTExpiredError`
- `verifyJWT` with malformed token (two parts) throws `InvalidJWTError`
- `decodeJWTUnsafe` returns payload without signature check
- Roundtrip: `issueJWT` → `verifyJWT` returns identical payload
- JWT header `alg` field is `EdDSA` and `crv` is `Ed25519`

### Integration Tests — `helix-api/tests/integration/vp.integration.test.ts` (additions)

- `POST /v1/vp/verify` with `session: false` → 200, no `session` field in response
- `POST /v1/vp/verify` with `session: true` → 200, response contains `session.token`, `session.expiresAt`, `session.publicKeyEndpoint`
- Returned JWT decodes to correct `agentDid`, `userDid`, `targetService`, `scopes`
- JWT `exp` is approximately `iat + JWT_SESSION_TTL_SECONDS` (within 2 seconds)
- `GET /v1/sessions/public-key` → 200, contains `publicKeyHex` and `alg: EdDSA`
- `GET /v1/sessions/public-key` response has `Cache-Control: public, max-age=3600`

### Security Tests — `helix-api/tests/security/jwt.security.test.ts`

- JWT issued after VP verify — verify JWT signature against `HELIX_JWT_PUBLIC_KEY` using `verifyJWT` from helix-core → valid
- Tamper JWT payload (base64url-decode, change `scopes`, re-encode without re-signing) → `verifyJWT` throws `InvalidJWTError`
- JWT issued for one `targetService` — manually decode and check it cannot be used for a different service (scope is in payload, enforcement is caller's responsibility — document this obligation in `self-verification.md`)
- `JWT_ISSUED` audit entry contains `jti` and `vpId` but does NOT contain the JWT token string itself
- `HELIX_JWT_SIGNING_KEY` does not appear in any audit log entry
- Expired JWT (manually set `exp` to past): `verifyJWT` throws `JWTExpiredError`
- `POST /v1/vp/verify` with `session: true` on a VP that fails verification → 400 `VP_VERIFICATION_FAILED`, no JWT issued, no `JWT_ISSUED` audit entry

### SDK Unit Tests — `helix-sdk-js/tests/unit/client/session.test.ts`

- `verifySessionToken` with valid JWT and correct public key returns payload
- `verifySessionToken` with expired JWT throws `JWTExpiredError`
- `verifySessionToken` with wrong key throws `InvalidJWTError`
- `verifyVP` with `session: true` passes correct flag to HTTP adapter

## Story 5 Acceptance Criteria

- [ ] `POST /v1/vp/verify` with `session: true` runs full VP verification then issues JWT — no JWT issued if VP fails
- [ ] JWT signed with `HELIX_JWT_SIGNING_KEY` (Ed25519, EdDSA alg) — separate from VC signing key
- [ ] `GET /v1/sessions/public-key` serves public key with 1-hour cache header
- [ ] `verifyJWT` in helix-core verifies without any external dependency — pure `@noble/curves`
- [ ] JWT payload contains `agentDid`, `userDid`, `targetService`, `scopes`, `vpId`, `jti`, `exp`
- [ ] `JWT_ISSUED` audit event emitted — token string never in audit log
- [ ] `HELIX_JWT_SIGNING_KEY` never in any log or audit entry
- [ ] All JWT security tests pass and none are skipped
- [ ] SDK `verifySessionToken` is a pure local call — no network
- [ ] `decisions.md` updated: confirm no jwt library added, Ed25519 manual JWT rationale documented
- [ ] OpenAPI spec updated for `session` field in verify request and response, and new public-key endpoint
- [ ] `scripts/setup.ts` generates `HELIX_JWT_SIGNING_KEY` + `HELIX_JWT_PUBLIC_KEY` alongside existing keys
